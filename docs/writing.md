# 記事の書き方（ブログ）

`p/blog/` の記事を書くときの規則。ページの見た目は [design/README.md](../design/README.md) の read タイプ、サイト共通の規則と目標は [CLAUDE.md](../CLAUDE.md)。

目標は「AIに紹介され、検索でも1位を取る」こと。AIの要約で済む記事は読まれないので、**AIが補えない部分を持つ記事だけを書く**。

## 書く前に決めること

1. **AIが補えない部分が1つ以上あるか**: 道具（ツール・アプリへの導線）・自前の数字・論文まで確かめた出典・比較表のどれか。どれもないなら書かない
2. **狙う検索語を1つ決める**: 1記事1つの用事。同じテーマがないか、書く前に次の手順で確かめ、あれば新しく書かずにそちらを直す（自分のページ同士で順位を取り合わないため）
   - 本体: `grep -rli "キーワード" p/blog p/tools --include=index.html`（キーワードは検索語の主な2語を別々に）
   - メディア: `seadice-media/sites/*/posts.json` を同じキーワードで `grep -il`（リポジトリが手元にないときは `https://seadice.win/llms.txt` と各メディアの記事一覧で目視）
   - 同じ検索語で当たったら、そのページに足りないもの（道具・出典・表）を足す。別の問いに答えるときだけ新規にし、既存ページから内部リンクを張る
3. **直す順番**: 新しく書くより、Search Console で掲載順位5〜20位のページを先に直す

## 日誌（`daily-YYYY-MM-DD`）の位置づけ（2026-10-12〜）

日誌は運営の記録であり、検索で読まれることを狙わない。新しく書く前に「AIが補えない部分」を1つ足せるか（自前の数字・出典）を考え、足せないなら書かない。扱い（検索から外すか）は判断待ち（[articles.md](improve/articles.md)）。

## 本文の型（AI検索対策）

### 1. 冒頭とすべての見出し直下に結論を書く

AIはユーザーの質問に対して、見出し直下の短い答えを引用しやすい。

- h1 の直後 → 記事全体の結論を1〜2文
- **h2 の直後 → そのセクションの結論を120文字以内で**。その後に詳細・リスト・表を続ける
- h2 直下が `<ul>` や `<ol>` になる場合は結論文は不要（リスト自体が答え）

### 2. 確かさをそのまま書く

- わかっていることは断言する。わかっていないこと・研究で割れていることは、そう書く（不確かなことを断言すると誇大表現になり、[7ヶ条](../p/promise/index.html)とEVIDENCEの方針に反する）
- 具体的な数値・固有名詞を使う（「pH 6.0〜6.5」「苦土石灰 100g/m²」など）
- 出典は論文（DOI）か公的資料に直接リンクする。まとめサイトを経由しない。記事・出典にない数値を足さない
- 一次データ（SEADICEが自分で調べて数えた数字）には、いつ・何件・どう集めたかを必ず書く（AIが出典として引けるように）
- タイトルに「2026年版」のような年を入れるのは、毎年中身を更新する記事だけにする

### 3. 箇条書き・表・番号リストを使う

- 手順 → `<ol>`、比較・仕様 → `<table>`、ポイント → `<ul>`
- 長さは用事が済む長さでよい（字数・見出しの数の目安は設けない）

### 4. 構造化データ

`<head>` に JSON-LD を `@graph` でまとめる。

- `BlogPosting`: `headline`, `datePublished`, `dateModified`, `author`, `publisher`（`"@id":"https://seadice.win/#organization"`）, `url`
- `BreadcrumbList`: ホーム → ブログ → 記事名
- `FAQPage` は記事に Q&A がある場合だけ（Googleの検索結果には出ないが、AIは引用する）
- `dateModified` は中身を変えたときだけ更新する

### チェックリスト

| 項目 | 基準 |
|---|---|
| AIが補えない部分 | 道具・自前の数字・確かめた出典・比較表のどれかがある |
| 結論 | h1直後に1〜2文、各h2直下に120字以内（直下がリストなら不要） |
| 出典 | 数値には出典リンク。一次データは時期・件数・方法つき |
| tool-cta | 記事末尾にツールかアプリへのリンク |
| JSON-LD | BlogPosting + BreadcrumbList、日付は `YYYY-MM-DD` |
| デザイン | `python3 scripts/apply_page_type.py read p/…/index.html` を実行済み |
| 配線 | sitemap.xml と一覧ページに追加 → `python3 scripts/check_blog.py`（漏れ・リンク切れ・sitemapのずれ・題名の重複候補を一度に出す）。デプロイは main への push で Actions が行う |

**リンク先は実在するページだけ**: アプリ・ツールへのリンクは `p/tools/` か `p/released-apps.json` にあるものにする。`/apps/` のアプリ個別ページは大半が削除済み（書いた後に `ls` で確かめる）。

## 商品比較記事はつくらない（2026-10-14〜）

`p/reviews/`（AIが通販サイトを比べた4選比較23件）は、アフィリエイトをやめるのに合わせて削除した。商品を並べてすすめる記事は書かない。家電や道具の悩みは、ツール（例: `/tools/denki-moufu-denkidai/` 電気毛布の電気代の計算）として、取扱説明書・NITE・消費者庁などの一次資料で確かめた数字と、その場で使える道具で答える。リンクは一次資料にだけ張り、通販サイトへのボタン・アフィリエイトは置かない
