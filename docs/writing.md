# 記事の書き方（ブログ・レビュー）

`p/blog/` と `p/reviews/` の記事を書くときの規則。ページの見た目は [design/README.md](../design/README.md) の read タイプ、サイト共通の規則と目標は [CLAUDE.md](../CLAUDE.md)。

目標は「AIに紹介され、検索でも1位を取る」こと。AIの要約で済む記事は読まれないので、**AIが補えない部分を持つ記事だけを書く**。

## 書く前に決めること

1. **AIが補えない部分が1つ以上あるか**: 道具（ツール・アプリへの導線）・自前の数字・論文まで確かめた出典・比較表のどれか。どれもないなら書かない
2. **狙う検索語を1つ決める**: 1記事1つの用事。`p/blog/`・`p/reviews/`・各メディア（seadice-media）に同じテーマがないか確かめ、あれば新しく書かずにそちらを直す（自分のページ同士で順位を取り合わないため）
3. **直す順番**: 新しく書くより、Search Console で掲載順位5〜20位のページを先に直す

## 日誌（`daily-YYYY-MM-DD`）の位置づけ（2026-10-12〜）

日誌は運営の記録であり、検索で読まれることを狙わない。新しく書く前に「AIが補えない部分」を1つ足せるか（自前の数字・出典）を考え、足せないなら書かない。扱い（検索から外すか）は判断待ち（[articles.md](improve/articles.md)）。

## 本文の型（AI検索対策）

### 1. 冒頭とすべての見出し直下に結論を書く

AIはユーザーの質問に対して、見出し直下の短い答えを引用しやすい。

- h1 の直後 → 記事全体の結論を1〜2文
- **h2 の直後 → そのセクションの結論を120文字以内で**。その後に詳細・リスト・表を続ける
- h2 直下が `<ul>` や `<ol>` になる場合は結論文は不要（リスト自体が答え）

```
良い例:
<h2>アブラムシの駆除方法</h2>
<p>アブラムシは水で洗い流すか、木酢液・牛乳スプレーで駆除できます。農薬を使わない方法を7つ紹介します。</p>
```

### 2. 確かさをそのまま書く

- わかっていることは断言する。わかっていないこと・研究で割れていることは、そう書く（不確かなことを断言すると誇大表現になり、[7ヶ条](../p/promise/index.html)とEVIDENCEの方針に反する）
- 具体的な数値・固有名詞を使う（「pH 6.0〜6.5」「苦土石灰 100g/m²」など）
- 出典は論文（DOI）か公的資料に直接リンクする。まとめサイトを経由しない。記事・出典にない数値を足さない
- 一次データ（SEADICEが集めた数字）には、いつ・何件・どう集めたかを必ず書く（AIが出典として引けるように）
- タイトルに「2026年版」のような年を入れるのは、毎年中身を更新する記事だけにする

### 3. 箇条書き・表・番号リストを使う

- 手順 → `<ol>`、比較・仕様 → `<table>`、ポイント → `<ul>`
- 長さは用事が済む長さでよい（字数・見出しの数の目安は設けない）

### 4. 構造化データ

`<head>` に JSON-LD を `@graph` でまとめる。

- `BlogPosting`: `headline`, `datePublished`, `dateModified`, `author`, `publisher`（`"@id":"https://seadice.win/#organization"`）, `url`
- `BreadcrumbList`: ホーム → ブログ → 記事名
- `FAQPage` は記事に Q&A がある場合だけ（Googleの検索結果には出ないが、AIは引用する）
- `dateModified` は中身を変えたときだけ更新する

### チェックリスト

| 項目 | 基準 |
|---|---|
| AIが補えない部分 | 道具・自前の数字・確かめた出典・比較表のどれかがある |
| 結論 | h1直後に1〜2文、各h2直下に120字以内（直下がリストなら不要） |
| 出典 | 数値には出典リンク。一次データは時期・件数・方法つき |
| tool-cta | 記事末尾にツールかアプリへのリンク |
| JSON-LD | BlogPosting + BreadcrumbList、日付は `YYYY-MM-DD` |
| デザイン | `python3 scripts/apply_page_type.py read p/…/index.html` を実行済み |
| 配線 | sitemap.xml と一覧ページに追加 → `firebase deploy --only hosting` |

## 商品比較記事（`p/reviews/`）

### 新しく作る条件（2026-10-12〜）

AIがWebで比較しただけの記事は、AIが自分でできる作業なので新しく作らない（Googleのレビュー評価でも下がる）。新しく作るのは、次のどちらかがあるときだけ。

- 実際に使った・測った結果（写真・数値）
- SEADICEの一次データ（ツールの匿名集計など）

既存の記事は残し、直すときは「書く前に決めること」の3に従う。

### 掲載場所

- パス: `p/reviews/{スラッグ}/index.html`（平置き）。一覧 `p/reviews/index.html` の先頭にカードを追加する
- ブログ（開発ブログ）とは混ぜない。トップページからの `/reviews/` 導線は置かない（2026-09-30〜）
- パンくずは `HOME / REVIEWS / {タイトル}`

### 書き方

- **構成**: 価格帯別（安い／中価格／高価格）に各2〜3商品
- **AIを使ったことの開示**: h1 直後に `.ai-badge`（見た目は design/ 側で管理）を置き、何を比べたかを書く。誇張・検証できない表現（「100サイト以上見て判断」等）は書かない
  ```html
  <div class="ai-badge"><strong>AIによる比較調査</strong><span>この記事はAI（Claude）が複数の通販サイトのレビュー・仕様（{比較した軸}）を比較して作成しました。</span></div>
  ```
- 型番・実売価格・仕様は `WebSearch` で複数の通販サイトから確認する。確認できない情報は書かない
- 本文の型は上の「本文の型」と同じ。末尾に関連アプリ・ツールへの tool-cta

### Amazonアソシエイト

- ID: `hide04261326-22`。リンクは `https://www.amazon.co.jp/dp/{ASIN}?tag=hide04261326-22`（`target="_blank" rel="nofollow sponsored noopener"`）
- ASINが確認できない商品はリンクせずテキストのみ
- 画像は使わない（外部リクエストゼロのため）
