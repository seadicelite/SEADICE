## 今後の展開（2026-11-03〜）

AIを使って信頼できる情報をWeb上にまとめ、そのデータをもとに、社会の問題を解決するWebサービス・アプリを作っていく。アプリの形はパクられても、信頼できる情報源としてのWebは真似されない。これがいちばんの強みになる。
- **AIは調べて照らし合わせる係**: 論文・公的データを全件当たる、数字を原文と比べる、AIの答えの出典を確かめる、などに使う。文章の量産には使わない（大量生成はスパム扱いになり、「盛らない」にも反する）
- **確かめた跡を見せる**: 主張ごとに出典・確かめた日・まだわからないことを付け、直したら訂正の履歴を残す。一次データには調べ方（どこを・何件・どう数えたか）も書く（他の人が同じ手順でやり直せるように）。AIのまとめが真似できない部分はここ
- **流れ**: AIで集める → 確かめて照らし合わせる → SEADICEのデータとしてためる → Webで公開（構造化して、AIにも人にも読みやすく）→ AI・検索に見つけてもらう → 紹介された人がツール・アプリを使う。いちばん大事なのは3つ目の「自分で調べてためたデータ」（既存のサイトの要約だけでは、AIがSEADICEを紹介する理由にならない）
- **データから作るものを決める**: 困っている人の数と、まだ解決されていない所をデータで確かめてから、サービス・アプリにする（アプリ企画の関門の「市場の選び方」と同じ判断。ニッチで、古参と競争相手が少ない所を選ぶ、2026-11-08）。調べた問題は [problems/](problems/README.md) の事業データベースにためる（需要・市場・競争・実現性・継続性で評価、2026-11-03〜、30日で50件）
- **メディアは何のためか**（2026-11-03）: 情報を発信すること自体は目的にしない。調べて社会の問題を見つけ、解決につなげるためのメディア。土台は「情報収集・研究」（正確に集めて整理し記録する）、目的は「社会問題の解決」（解決方法を考え、必要ならサービスを作る）。「市場調査・分析」は作るものを決める判断に使い、結果は事業データベース（problems/）にためる（読者向けの記事にはしない）
- **サイトの役割は3つ**（2026-11-03）: ①情報提供（正確で役立つ情報を体系的に。転載でなく、比べて分析した独自の結果を）②問題解決（その場で使えるツール）③サービス提供（続けて使うWebアプリ・アプリ）。AI検索への対策は、この土台（正確さ・独自性・運営者情報・わかりやすいページ構造）ができてから進める。AIに紹介される保証はない
- **1テーマで型を作ってから広げる**: 最初は AI詐欺（公的統計＋AIの答え合わせ → BOHAN・hanzai・EVIDENCE → AIBOU・怪しい人チェック）

## 作るもの = AIが補えない部分

記事（メディア）だけでなく、サイトの中に次のものを作る。AIはチャットで答えが済む質問ではサイトを紹介せず、検索でもAIの要約で済む質問はクリックされない。どちらでも勝てるのは、この部分だけ。

| AIが補えないもの | 例 |
|---|---|
| 実際に動く道具 | 計算・チェック・タイマー・診断（ブラウザ内で完結） |
| 続ける記録 | 端末内に保存して経過を見る（登録なし） |
| 一次データ | SEADICEが自分で調べて数えた数字（例: 論文・公的統計を全件当たった集計）。**利用者からはデータを集めない**（匿名の集計・カウンターも作らない、2026-10-13。例外はAPIの使いすぎを防ぐための呼び出し回数だけで、中身は記録しない、2026-10-15。もう1つの例外は利用者が自分で公開する投稿で、匿名の掲示板アプリなどで投稿内容と匿名IDだけを保存し、IPや端末情報はためない、2026-10-27） |
| 確かめた出典 | 論文まで当たった研究のまとめ（EVIDENCE。AIは出典を間違える） |
| 体系と網羅 | 講座・マップ・全件の比較表（日付つき） |
| 手元に残るもの | 印刷テンプレート・アプリ |

- 1ページ1つの用事にして、そのページだけで用事が済むようにする（検索1位とAIの紹介の両方の条件）
- ページを作る・残すかは「AIや検索が紹介する理由があるか」で決め、似たページは増やさずまとめる
- 狙う検索語は、答えより道具や記録が欲しい語（「〇〇 計算」「〇〇 チェック」「〇〇 記録」など）を優先する
- **悩み・問題の検索語で1位を取る価値は大きい**（2026-10-13）。中身の一部がAIで代わりがきくページでも、それを理由に消したり作るのをやめたりしない。そのページに道具・確かめた出典・続ける記録を足して1位を取りにいく。いろいろな悩みの1位に毎回「SEADICE」が出ることで、SNSを使わなくても名前を覚えてもらえる

## 1番の取り方（縦に深く、横に広く）

どのジャンルでも1番を目指すが、一度に全部は狙わない。
- **縦**: 狭いテーマ1つで、問いを網羅し（テーマ×問いの表を埋める）、どの問いにも「結論＋確かめた出典＋使える道具」をそろえて1番を取る
- **横**: 1番を取った型（よく聞く説を研究で確かめる → 道具で試す → アプリで続ける）を、隣のジャンルへ広げる。順番は、すでに資産がある所から: EVIDENCE → 診断（/diagnosis/）→ 人相・しぐさ（umbra）→ 防犯（BOHAN）→ 占い（血液型・星座など）
- **勝つ相手**: 根拠のない記事・物を売るための記事・広告だらけのまとめ。こちらは「出典を確かめた結論」「まだわからないことも書く」「売らない」「その場で使える道具」で勝つ。大手のニュースサイトにはドメインの強さで負けやすいので、AIの引用と、具体的な問い1つ1つのページで先に勝つ
- 今どのテーマを攻めているかは [improve/README.md](improve/README.md) の「攻めているテーマ」に書く

## SEOとAIの順位には賭けない、誠実に積み重ねる（2026-11-03）

順位の決め方も、AIの記事が増えた先でどう選ばれるかも、誰にもわからない。予想に賭けず、次の3つで進める。
- **変わりにくいものに力を使う**: 確かめた出典・自分で数えた数字・使える道具やアプリ・わからないことも書く誠実さ
- **小手先のSEOに時間をかけない**: キーワードを詰める・本数を水増しする・似たページを増やす、はしない。量より「狭く・全部・深く」。title・description・構造化データなどの基本はスクリプトで済ませる
- **自分の数字で確かめる**: 効いているかは外の説でなく、Search Console のクリックと月1回のAIへの質問（下の1と3）で決める。新しいテーマは期限を決めて試し、出なければ増やさない

## リスクベースのサービス設計（2026-11-03〜、詳細）

攻撃（AIによる無制限の攻撃を含む）に正面から勝とうとせず、攻撃されても大したことにならない作りにする。
1. **洗い出す**: 何が狙われるか・破られたら何が起きるか（情報の流出・なりすまし・荒らし・詐欺・請求の膨張・法律の義務）を表にする。サーバー・ログイン・投稿・課金・外部APIのどれかがあれば `security` 役が作る
2. **持たない**: 盗まれて困るものは最初から持たない。カード情報は Apple・Stripe、本人確認は Firebase Auth に任せ、SEADICE の手元は uid と本人が公開したものだけにする
3. **上限を付ける**: 呼び出し回数・予算アラート・予算を超えたら止める仕組み・App Check で、最悪の被害と費用に天井を作る
4. **止められるようにする**: 何かあったらサービスを一時停止できるスイッチを、公開前に用意する
5. **残ったリスクは書いて受け入れる**: 防ぎきれない分は、表に「受け入れる理由」を書いて進む。運営者の2段階認証など人の手が要るものは manual.md へ
