# App Store のモックアップ（全アプリ共通）

App Store に出すスクリーンショット・ヘッダー・検索結果の画像の決まり。新規申請でもアップデートでも、ストアの画像を作るときは毎回これに従う（初版 2026-10-13）。

**モックアップ = 見出しの文字＋実際の画面**。実画面だけ・文字だけの絵は出さない。

**目標: 見た人がダウンロードしたくなること**（スクショもアプリプレビューも、2026-11-09 ユーザー）。言葉と形は、脳科学マーケティング（[neuro.md](neuro.md)）の確かさA・Bの研究で決める。ただし煽り・偽の数字・価格の言葉は使わない（誠実が上）。

## 1. 作る順番（言葉が先）

1. **見出しは Claude が決める**（2026-11-09 ユーザー判断「選ぶのが面倒、脳科学マーケティングをベースに、よりダウンロードしてもらえそうな言葉を選んで。信用してます」。それまでは表で出して選んでもらっていた）。[neuro.md](neuro.md) の確かさA・Bの原則で選び、決めた見出しと選んだ理由を一言ずつ報告に書く。ユーザーが直したいと言ったときだけ直す。スクショと動画の両方に当てる
2. 実画面を撮る（下の「5. 実画面の撮り方」）
3. `python3 scripts/mockup.py {アプリのフォルダ} --init` で `screenshots/mockup.json` のひな形を作る。実画面からアプリの色を拾った**配色3案**が出るので、選んだ見出しと一緒に書く（make.py をアプリごとに写すのは 2026-11-09 にやめた。古いアプリの make.py はそのままでよい）
4. **形と配色を選んでもらう**: 選んだ見出しを mockup.json に入れてから（見比べ用の絵に見出しを使うため）、`python3 scripts/mockup.py {アプリのフォルダ} --styles` で、1〜3枚目を全部の形（下の「3. 形」）で描いた `screenshots/styles.png` を見せ、形・書体・本体の枠の有無・配色を選んでもらう
5. `python3 scripts/mockup.py {アプリのフォルダ}` で書き出す（App Store での見え方の画像は、APPSTORE_SUBMISSION.md の「## アプリ名」か1行目の `# {アプリ名} {版}` からアプリ名を読む。1行目を「# App Store 提出情報 — 1.1.0」にすると、それがアプリ名として出る。2026-11-10）。下の表の全枠（日英）を書き出し、価格の言葉と実画面の抜けがあれば止め、サイズを確かめ、全部を並べた `screenshots/check.png` と App Store での見え方（`scripts/appstore_preview.py`）を作って、Finder とプレビューで開く。チャットにはフォルダの場所と、出てきた見出しの表を出す
6. **アプリプレビュー（動画）も同じ作業で必ず作る**（「7. アプリプレビュー」。2026-11-09 ユーザー指摘: スクショだけで止めて「動画はないの？」と聞かれた）。見出しはスクショと同じく Claude が決める

置き場所: アプリのフォルダの `screenshots/` に枠ごとのフォルダ（例: `screenshots/6.3/1.png`。ヘッダーと検索結果は `header/3840x1646.png` のようにファイル名をサイズにする。英語は `screenshots/en/…`）

- 6.9インチ（1320 × 2868）は今は使っていない。必要になったらこの表に足す

## 3. 形（`scripts/mockup.py`、mockup.json で選ぶ）

- **スクリーンショット**（縦）は4つの形から、アプリに合うものを選ぶ（2026-11-09。どれも見出しと実画面の2つでできていて、文字だけ・絵だけにはしない）

| style | 形 | 合うアプリ |
|---|---|---|
| `classic` | 上に印と見出し2行（中央）、下に実画面 | 迷ったらこれ |
| `split` | 地が画面の途中で淡い色に変わり、画面が境目にまたがる | 明るい・やわらかいアプリ |
| `bold` | 左上に番号（01〜06）、大きな見出しを左寄せ、画面を右へはみ出させる | 学び・記録・手順があるアプリ |
| `panorama` | 6枚を並べると、地の円と帯がつながる | 6枚の流れで見せたいアプリ |

- `device: true` で iPhone・iPad の本体の縁を描く（実画面にステータスバーがないときは、画面の上の色で帯を足してダイナミックアイランドを置く。ステータスバーがある実画面なら `status_bar: true`）
- 書体は `font` で、ヒラギノ角ゴ（`gothic`、既定）・丸ゴ（`maru`）・明朝（`mincho`）か、アプリの書体ファイル（例: `assets/fonts/NotoSansJP-VariableFont_wght.ttf`）。アプリの中と同じ書体にすると、画面と見出しがそろう
- 配色は、`--init` が実画面から拾ったアプリの2色（主な色と、印やボタンのアクセント色）で作る3案（アプリの色の地・淡い地・黒に近い地）から選ぶのが基本。2行目はアクセント色にする（1色だけだと2行目がくすむ）
- 見出しは詰め組み（句読点・括弧を半角幅、字間を少し詰める）。印は細い線の枠にする（塗りつぶすと見出しより目立つ）
- **拡大窓**（`focus: [x, y, 幅, 高さ]`、実画面に対する割合）: 見出しが指す実画面の大事な所を、元の場所の上に約1.2〜1.3倍で浮かせる（アクセント色の枠・角丸8px・影なし）。見る所に印を付けると理解が上がる（Schneider ほか 2018、シグナリングのメタ分析・A。学習の研究で、ストアへは外挿）。拡大するのは実画面にある本物の部分だけ。1〜3枚目には必ず付ける。iPad は、iPhone の focus と同じ所を iPad の実画面から画像照合で探して自動で当てる（見つからないと注意が出るので、そのときだけ `focus_ipad`・`crop_y_ipad` を書く）
- `crop_y`（0〜1）で実画面の上を切り、見せたい所を枠の上半分に入れる（画面が下まで届く所までしか切らない）。実画面がほぼ同じ枚が並ぶと注意が出る
- 文字は検索結果の小ささでも読める大きさ（見出し 116、補足は太字 54。1206px幅のとき）。長いと小さくして収めるが、それでは読めなくなるので言葉を短くする
- 色の役割は2つ: アクセント色は2行目と拡大窓の枠だけ。文字と地のコントラストは 4.5:1 以上（2行目は大きい文字なので 3:1）で、足りないと書き出しを止める
- **ヘッダー・検索結果**（横）: 左に印・見出し2行・補足、右に実画面を大きく（下へはみ出させる。入りきらないと台数を減らすので、検索結果はふつう1台）。1台目には縦のスクショと同じ拡大窓が付くので、`wide.shots` の1つ目は1枚目と同じ核の価値の画面にする
- グラデーション・ぼかし・影は使わない（質実剛健）。絵文字は使わない
- 実画面はアプリの今のバージョンのもの。サンプルデータは、それらしい中身を入れる（空の画面・エラー・個人名を写さない）

## 4. 見出しの書き方（neuro 役、2026-11-09）

検索結果では1〜3枚目が小さく並び、読めるのは見出し2行だけ。人は一瞬で入るか決める。

**型**
- 1行目: 自分の場面か悩み（8〜10字）。2行目: できること。数か動詞を入れる（10字以内）。補足: 何でできるかと安心の一言
- 1行9字前後まで（`scripts/mockup.py` は10字を超えると注意を出す）。1枚に置く言葉は、見出し2行と補足1行まで
- 見出しと実画面は同じ所を指す。見出しが指す部分を `focus`（拡大窓）で大きく見せ、`crop_y` で枠の上半分に入れる
- 不安を書くなら1行までにし、同じ枚に対処を書く（怖がらせるだけの見出しは効かない。Tannenbaum ほか 2015、恐怖訴求のメタ分析・A）。「今すぐ」「手遅れになる前に」は書かない
- 数字はアプリの中にある数だけ（5つのサイン・相談先2つ・手順4つ）。利用者数・評価・順位・「○%」は書かない
- 研究にもとづくアプリは「研究で使われる〜」「論文で確かめた〜」のように、根拠の出どころを短く入れてよい
- 書かないこと: 「科学的に証明」「必ず」「当たる」「見抜ける」、中身にない機能（AIを外したアプリに「AI」）、価格の言葉（下の「価格の言葉」）

**6枚の役割**（最初に見たものほど残る。1〜3枚目で用事が伝わるように）

| 枚 | 役割 | 例（怪しい人チェック） |
|---|---|---|
| 1 | 核の価値: 何がわかる・何ができるか | マッチングの相手を／5つのサインで見る |
| 2 | 手軽さ: どれだけ簡単か | スクショを選ぶだけ／iPhoneの中で判定 |
| 3 | わかった後にできること | お金の話が出たら／相談先にすぐ電話 |
| 4 | 広がり: ほかの使い方 | プロフィールも／業者の書き方を探す |
| 5 | 別の人・場面（家族など） | 親の相手が心配なら／話し方の見本つき |
| 6 | 安心・その後 | もう送ってしまっても／4つの手順で動ける |

例は 2026-11-09 の見本で、ユーザーはまだ選んでいない。

### 価格の言葉（「無料」）を書いてよい場所

「無料」「無償」「0円」「課金なし」「割引」「セール」「お試し」「月額」「サブスク」、英語の Free なども価格の表記になる。「No.1」「best」のような確かめられない最上級も同じ Guideline で止める（`scripts/mockup.py` が止める。英語の「Ad-free」は価格ではないので止めない）。アプリに課金があるかどうかに関係なく、メタデータに入れると Guideline 2.3.7 で却下される（2026-10-16 そのリンクちょっと待ったで実例。バッジ「無料・広告なし・登録なし」と、実画面に映ったAIの返事の「無料」）。

| 場所 | 価格の言葉 |
|---|---|
| スクショ（バッジ・見出し・実画面の中）・プレビュー動画 | 入れない |
| アプリ名・サブタイトル・アイコン | 入れない |
| キーワード | 入れない（明記はないが指摘されることがある） |
| 説明文・プロモーションテキスト | 書いてよい（Apple も説明文に書くよう案内している） |
| アプリの中の画面・seadice.win のページ | 書いてよい。ただしその画面をスクショに使わない |

バッジは「広告なし・登録なし」のように価格以外の約束だけにする。

## 5. 実画面の撮り方

- 背景が明るい色（ティールなど）のときは、2行目を白にしない（読めない）。濃い同系色にする（見本: 通知de人生改善の screenshots/make.py）
- 既定: `python3 scripts/mockup.py {アプリのフォルダ} --init-shots` で撮影用テストのひな形を作り（パッケージ名・起動する Widget・アプリの書体・package_info_plus の仮の値は自動で入る。2026-11-10 怪しい人チェックの写しで、ひな形のまま iPhone・iPad を撮れた）、TODO の保存データと画面の操作を書く。アプリに `test_screenshots/shots_test.dart` を置いて `flutter test test_screenshots/shots_test.dart --update-goldens`（本物のフォントとサンプルデータで描ける。見本は Spendology）。Cupertino のタブの文字とアイコンにもフォントを読み込ませる（読み込まないと□になる）。`appBarTheme.titleTextStyle` に `fontFamily` がないアプリは、テストではタイトルが□になる（どの名前でフォントを読ませても直らない）。テスト側でアプリのテーマを写し、タイトルにだけフォントを足す（見本: 貿易実務英単語の test_screenshots/shots_test.dart、2026-10-20）。問題や単語がシャッフルされるアプリは、`flutter/assets` をモックして写す問題だけを差し込む（同じ見本。50KBを超えるJSONは別のisolateで読まれるので `tester.runAsync` で本物の時間を待つ）
- 実画面にも価格の言葉を映さない（書き出しのときに文字認識で確かめて止める）。サンプルの文章・例文・AIの返事に「無料」が出ないものを選ぶ（AIにサイトを調べさせる画面で seadice.win を使うと説明に「無料」が出る。気象庁などの公的サイトを使う）
- テストで描きにくい画面は、Web版（`flutter build web`）をブラウザで動かして撮ってもよい。どちらも、最後に共通の形で合成する

## 7. アプリプレビュー（動画、モックアップと一緒に必ず作る）

`scripts/app_preview.py` で作る（2026-11-09）。Apple の決まり: **中身はアプリの画面を録画したものだけ**（文字を重ねるのは可。手や本体の写真・アプリにない絵は入れない）、15〜30秒、30fps。

**まだ確かめていないこと**（初めて出したアプリの結果で、ここを書き直す）: 左に見出し・右に縮めた録画という形が審査で通るか、無音の音声トラックが要るか（音声なしで受け付けられるかわからないので、Apple の音声の書き方（ステレオ・AAC・48kHz）に合わせた無音を入れている）

1. シミュレーターでアプリを起動し、`python3 scripts/app_preview.py {アプリのフォルダ} --record 1` で録画する（操作して Enter で止める → `screenshots/rec/1.mov`。Claude が録るときは `--seconds 20` で止める）。iPad は iPad のシミュレーターで録り、`screenshots/rec_ipad/` に同じ名前で置く（無ければ iPad のプレビューは作らない）。英語は `rec/en/`
   - **iPad の録画は、`recordVideo` の始まりが数秒〜10秒ずれることがある**（2026-11-11 テス活ログ。SCENE の時刻から出した start で、ホーム画面が映った）。書き出したら2秒おきのコマを並べて場面の時刻を確かめ、iPhone とずれていたら `ffmpeg -vf tpad=start_duration=秒:start_mode=clone`（足す）か `-ss 秒`（切る）で iPad の録画の時刻を iPhone にそろえる（preview.json の start は iPhone と iPad で共通）
   - **Claude が録るときは、操作を integration_test に書いて動かす**（2026-11-10 FBI式ボディランゲージ辞典。シミュレーターの画面を cliclick で押そうとすると前面のアプリが入れ替わってタップが届かず、プレビューが後回しになった）。`integration_test`（dev_dependencies）に `integration_test/preview_test.dart` を置き、場面の始まりに `SCENE n <時刻ms>` を出して、`xcrun simctl io <端末> recordVideo` で録りながら `flutter test integration_test/preview_test.dart -d <端末>` を走らせる。録画の開始時刻との差が preview.json の start になる。ランダムな出題は、スクショのテストと同じ「正解の文のリスト」で押す。見本: 心理学系/fbi-bodylanguage/integration_test/preview_test.dart。押した所に緑の十字（テストのタップの印）が映る
2. 場面の順番と見出しはスクショと同じ型（「4. 見出しの書き方」の型と6枚の役割の1〜3）。最初の場面で核の価値を見せる。見せる場面ごとに `screenshots/preview.json` に書く: `{"clips": [{"video": "1.mov", "start": 0.5, "end": 6, "lines": ["1行目", "2行目", "補足"], "focus": [x, y, 幅, 高さ]}]}`。`focus` はスクショと同じ拡大窓で、録画の大事な所を切り抜いて拡大し、元の場所の上に重ねる（録画と一緒に動く。iPad は iPhone の録画で決めた場所を自動で探す）。見出しはスクショと同じく Claude が決める。**3場面×5秒＝15秒を基本にする**（短いほうがよい、2026-11-10 ユーザー。Apple は15秒より短いと受け付けないので15秒が下限。15秒を超えると注意が出る）
3. `python3 scripts/app_preview.py {アプリのフォルダ}` で、**1920 × 886（iPhone）と 1600 × 1200（iPad）**を書き出す（左に見出し、右に録画を角丸の枠で。色と印は mockup.json から）。サイズ・長さ（29.9秒まで）・30fps を確かめ、無音のステレオ音声を入れる。preview.json の書き間違い（start・end が録画の長さを超える、見出しが3つでない）は書き出す前に止める。出力は `screenshots/preview/{iphone,ipad}.mp4`
4. 価格の言葉は見出しにも録画の中にも映さない（「価格の言葉」の表と同じ。書き出した動画の1秒ごとのコマを文字認識で読んで止める）。左の見出しはスクショと同じ形（線の印・詰め組み）

## 8. 効いたかを見る（2026-11-10）

目標はダウンロードなので、差し替えたら数字で確かめる。数字は Apple が集計するものだけを使い、利用者からデータを集めない。

- **差し替えたら下の表に1行足す**（申請が通って公開された日）
