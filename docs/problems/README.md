## 1件の書き方

1件1ファイル `NNN-slug.md`（例: `001-tokushu-sagi.md`）。[_template.md](_template.md) をコピーして使う。

| 項目 | 書くこと | 種類 |
|---|---|---|
| 問題 | 何が起きているのか | 調査結果 |
| 対象者 | 誰が困っているのか（年代・立場・人数） | 調査結果 |
| 発生頻度・規模 | どれくらい起きているか（件数・割合・推移） | 調査結果 |
| 被害規模 | どれくらいの損失があるか（金額・時間・健康など） | 調査結果 |
| 公的統計 | 公的機関・調査機関の数字（表の名前・年・数字） | 調査結果 |
| 既存サービス | すでにある解決策（公的窓口・企業のサービス・アプリ） | 調査結果 |
| 不満・不足 | 今の解決策に足りないもの | 調査結果（口コミ・調査）と推測を分けて書く |
| AI・Webで解ける所 | AIやWebサービスで解決できる可能性 | **推測** |
| 事業機会 | SEADICE が参入できる余地（既存の資産・勝ち筋・お金を払う理由） | **推測** |
| 情報源 | 本文の番号 [1] と対応するURL・資料名・発行元・公表日 | — |
| 確認できないこと | 調べたが見つからなかったこと | — |

## 守ること

1. **出典を付ける**: 数字・事実には文末に [1] のように番号を付け、「情報源」に対応させる。優先順は 公的機関（警察庁・消費者庁・総務省・厚労省・内閣府など）→ 調査機関・学術論文 → 企業の公式資料。まとめサイト・個人ブログは出典にしない
2. **推測で埋めない**: 見つからない項目は「確認できない」と書く。空欄やそれらしい数字で埋めない
3. **調査結果と推測を分ける**: 「AI・Webで解ける所」「事業機会」は推測なので、見出しに（推測）と付ける。調査結果の欄に意見を混ぜない
4. **数字は原文と照らす**: 公表年・単位（件／人／円）・対象範囲（全国か一部か）を原文のまま書く。二次資料の数字は一次資料まで当たる。統計の定義が変わった年は、ファイルの頭に書く（例: 警察庁は令和8年から SNS型投資・ロマンス詐欺を特殊詐欺に含めて数えるので、令和7年以前とそのまま比べない）
4-2. **原文を開かない調べ方でもよい**（2026-11-04〜、トークンを抑えるため）: ページやPDFを開かず、検索結果の抜粋だけで書いてよい。そのときは数字ごとに「（原文未確認）」と付け、出典には検索結果で見えた発行元・資料名・URLを書く。原文まで当たった数字は印なし。判断が「追う」になって作る前に、使う数字だけ原文で確かめて印を外す
5. **調べた日と調べ方を書く**: ファイルの頭に「調べた日」と「調べ方」（どこを・どう探したか）を書く。他の人が同じ手順でやり直せるように
6. **更新したら履歴を残す**: 新しい年の統計が出たら数字を直し、末尾の「更新履歴」に日付と何を変えたかを書く

## 評価（各ファイルの最後に書く）

5つの基準を ○（満たす）／△（一部・未確認）／×（満たさない）で付け、根拠を1行ずつ書く。根拠は上の調査結果の番号を引く（推測で付けたものは「推測」と書く）。

| 基準 | 確認すること | ○の目安 |
|---|---|---|
| 需要 | 本当に困っている人がいるか | 被害・相談件数などの公的な数字がある |
| 市場 | 対象者は十分に存在するか | 対象者が数十万人以上（CLAUDE.md の「中規模以上の市場」） |
| 競争 | 既存サービスで解決できているか | 既存サービスに、調べて確かめた不足がある |
| 実現性 | 自分の技術と資金で作れるか | 個人で、登録・個人情報の収集なし、サーバー代を抑えて作れる |
| 継続性 | 3〜5年後も必要とされるか | 数字が増えている・構造的な問題で、流行で終わらない（「5年続けられるか」） |

**判断**:
- **追う**: ×がなく、○が4つ以上。サイトの3つの役割のどこから作るかも書く
- **保留**: △が残っていて、調べれば○か×に決まる（何を調べるかを書く）
- **見送り**: ×が1つ以上（特に、SEADICE の約束——登録・個人情報の収集をしない、広告なし、医療の判断をしない——と両立しないものは実現性を×にする）

「追う」になったものは、サイトの3つの役割（情報提供・問題解決・サービス提供）のどこから作るかを決めて、該当分野の docs/improve/ の「次にやること」に足す。
