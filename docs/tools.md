# ツールの作り方（ブラウザツール・診断）

`p/tools/` のブラウザで動くツールと `p/diagnosis/` の診断を作る・直すときのルール。見た目は [design/README.md](../design/README.md) の use タイプ、サイト共通の規則と理念は [CLAUDE.md](../CLAUDE.md)。このルール自体も [docs/improve/tools.md](improve/tools.md) で毎週見直す（初版 2026-10-12）。

ツールは「AIが補えない部分」の本体。**ユーザーの悩みを、このページだけで解決する道具**にする。

## 1. 作る前に決めること
- どの悩みから来たか（メディアの記事・EVIDENCE のトピック・ユーザーの声）
- AIのチャットでは済まない理由: 計算する・記録して経過を見る・比べる・チェックする・手元に残す のどれか
- 狙う検索語を1つ（「〇〇 計算」「〇〇 チェック」「〇〇 記録」など）。同じ用事のツールがすでにあれば、新しく作らずそちらを直す

## 2. 操作
- 最初の操作は1タップで始められる。硬いフォームにしない（気分を1タップ → 短い選択肢 → 任意のメモ、の順）
- 文言は話し言葉で柔らかく。ボタンは「送る」でなく「結果を見る」のように具体的に
- 良い例（形）: `p/tools/kyukei-timer/`。冒頭に悩み（集中が続かない）への一言、選択肢2つ（10分+90秒／25分+5分）を押すだけで準備でき、「スタート」1タップで始まる。結果の読み方・根拠・FAQ が操作部の下に続く（出典リンクの足りなさは別の課題）
- 入力欄・ボタンは高さ48px以上、入力項目は最小限

## 3. 記録とプライバシー
- 登録なし・送信なし。記録はブラウザ内（localStorage）だけに保存し、読み書きは try/catch で囲む（保存できない環境でも使えるように）
- 記録は書き出して持ち出せるようにする（テキストかJSON）
- 外部へのリクエスト（fetch・外部スクリプト・外部画像）を入れない

## 4. ページの並び
ツール本体 → 結果の読み方 → 根拠と出典 → よくある質問 → 関連（記事・EVIDENCE・アプリ）

## 5. 根拠と表現
- 計算式・判定の基準には出典（論文・公的資料）を書く。記事へのリンクだけで済ませず、「出典」の節に論文は DOI、公的資料は URL を直接リンクする（2026-10-12 の点検で、ブラウザツール26件中16件にリンクがなかった）。DOI を引けない環境では `p/apps/evidence/data/topics.json` の `sourceUrl` で照合済みのものを使い、確認できない出典は「未確認のためリンクしていない」と書く（推測で DOI を書かない）。診断は研究での裏付けの強さを信ぴょう性ランク（A〜D）で示す
- **研究をもとにした道具は、機能を主役にし、研究は専用の画面に分けて省略せずに見せる**（2026-10-14、ユーザー判断）: 開いて最初に出るのは道具。上のタブ（例: 「1分リセット」「記録」「研究 9本」）で研究の画面に切り替え、研究は結論・どんな研究か・数字・まだわからないこと・出典（論文へのリンク）まで全部載せ、1文も削らない。**文字が多くなりがちなので、文章はできる限り折りたたむ**（2026-10-14、ユーザー判断）: 研究は1本ずつ `<details>` にし、閉じた状態でも問いと結論の1文は見せる（「よく聞く説」から始まる研究は「ほんとのところ」のカードを見せる）。「すべて開く」を置く。冒頭の説明は結論の1文だけ残し、使い方・保存の説明・一覧表も折りたたむ。効かなかった研究も同じ扱いで載せる。各手順には「根拠を見る」を付け、研究の画面の該当する研究を開いた状態で飛ばす。文章は topics.json のカードから書き出し、手で写さない。見本: `p/tools/shisei-reset/`
- 「科学的に証明された」「当たる」「〜がわかる」と言い切らない。病気の診断・治療の助言はしない

## 6. 技術
- `python3 scripts/apply_page_type.py use p/…/index.html`。操作部の要素に `sd-tool` クラスを付けてから実行
- JS は最小限・インライン。エラー時に入力を消さない
- 点数式（○件法で合計する）の診断は、独自JSを書かず共通エンジン `/diagnosis/assets/likert.js` を使う（結果は診断プロフィール帳に自動で記録される）。研究の平均がない尺度は `mean` を書かずに `bands`（点数の区切り）で判定し、区切りはSEADICEが決めたと本文に書く。タイプが多いときは `"sortByScore": true` で高い順に並べる。研究に年代・性別などの平均があるときは `norms`（くらべる相手を選ぶチップ。`groups` に「軸1|軸2」ごとの平均とSD）を入れ、利用者に近い集団とくらべられるようにする（大学生の平均だけで判定すると、成人の多くが「高め」に偏る）。平均とSDがあれば `"percentile": true` で「100人中の目安」を出し、正規分布を仮定した目安だと本文に書く。前回との差は全診断で自動で出る（端末内の履歴）。相手や場面ごとに答える尺度（「その人は〜」と聞く尺度）は、答える前に1タップで選ばせる `pick`（`{"axis": norms の軸番号, "lead": "「{label}」を思い浮かべて…"}`、選択肢は intro の `.pick-chip`）を使い、平均の比較と前回との差も選んだ相手ごとにする。2つの尺度の高低で型に分ける診断は `quadrant`（`x`・`y` の尺度、`cut` は1問あたりの区切り、`types` の "yx" = "00"〜"11"）で型と位置の図を出し、区切りはSEADICEが決めたと書く（研究では型より連続した強さのほうが実態に合うことが多い）。全項目の合計でも段階を出したいときは `total`（`{"name", "min", "max", "bands"}`。結果の `.total-box` に段階を出し、共有文も段階になる。前回との差は合計と変わった項目だけ）。見本: `p/diagnosis/bigfive-tipi/`（平均・norms・percentile）、`p/diagnosis/enneagram/`（bands・9タイプ）、`p/diagnosis/attachment-style/`（pick・quadrant・相手別の平均）
- use タイプは PC で操作パネルを右側に固定する。項目が多く画面より長くなるパネルは、固定すると下のボタンが画面外に残るので、ページ側で `body.t-use main>#app.sd-tool{position:static}`（960px以上）を足して固定を外す（見本: `p/tools/dekakeru-mae-tenken/`）
- title と h1 に狙う検索語。JSON-LD は WebApplication（`publisher` は `"@id":"https://seadice.win/#organization"`）＋ BreadcrumbList（＋ FAQPage）
- sitemap・ツール一覧（`/tools/`）・llms.txt に追加
