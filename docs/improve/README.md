## 2つの改善（ページとルール）

```
理念（ユーザーのために考え抜く）
 └ 目標（AIに紹介され、検索で1位）
    └ 各分野の目的
       └ 各分野のルール（デザイン・内容・作り方）  ← ルールを良くする
          └ ツール・アプリ・記事・ページ          ← ページを良くする
```

- **ページを良くする**: ルールに照らして点検し、ずれを直す（各ファイルの「次にやること」）
- **ルールを良くする**: そのルールがユーザーのためになっているかを問い、ルール自体を直す（各ファイルの「ルールの次にやること」）。同じ問題が二度出たら、ページを直すだけでなくルールで防ぐ
- 毎回、両方を1つずつ進める。ルールを変えたら「ルールの変更履歴」に日付と理由を書く

## 直し方の約束（全分野共通）

- **すぐ直してよいこと**（各ファイルに列挙）は、ルーティンが main に直接 push する。push すると Actions がデプロイと IndexNow 通知まで行う
- **各分野のルール文書の改善**（言い回しの明確化・実態に合わせる・矛盾の解消・再発防止のルールの追加・効かないルールの削除）は、変更履歴に理由を書いて main に push してよい
- **判断が必要なこと**（理念・目標の変更、ページの削除・統合、noindex の付け外し、収益にかかわる記述、デザインの大きな変更）は PR にするか、ファイルの「次にやること」と manual.md に書くだけにする
- 1回で直すのは1テーマまで。大きく作り直さず、毎日少しずつ（改善は徐々に）
- 絵文字禁止・広告なし・登録なし・「証明された」と書かない・p/index.html（トップ）は触らない
