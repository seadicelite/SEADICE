# デザイン（火曜）

## 目的
読む・魅せる・使うの用事が最短で済む見た目にする。質実剛健（飾りなし）で、どのページも同じサイトだとわかること。

## この分野のルール
design/README.md・design/*.css

## ルールを良くする（毎回1つ問う）
ページを直すだけでなく、その下にあるルールもユーザーのために良くしていく。
- このルールは、ユーザーの悩みの解決に効いているか（効いていない・古い・足りないルールはないか）
- 今回の点検で見つかった問題は、ルールがなかった・あいまいだったせいではないか（同じ問題が二度出たら、ルールで防ぐ）
- 守る手間がかかるだけで、ユーザーのためになっていないルールはないか

### ルールの次にやること
1. 生成スクリプトは書き出し時に必ず apply_page_type.apply を通す（build_apps_page.py と build_evidence_hub.py は対応済み。新しい生成スクリプトにも）
2. 新しいページは公開前に `grep -rL '<body class="t-'` で適用漏れを確かめる（同じ漏れが2回出たら、公開手順のチェックに入れる）
3. 3タイプそれぞれに「ユーザーの用事がいちばん早く済む形か」の基準を1行ずつ足す

## 良い状態
- p/ のページが read / show / use のどれかで、design/ の CSS が当たっている（`<body class="t-…">`）
- グラデーション・ぼかし・光・影・8pxを超える角丸がない（生成スクリプトが書き出すページも同じ。独自CSSを書く場合も守り、可能なら apply_page_type.py を通す）
- 使うページ（ツール・診断）は、フッター先頭に最終更新日（`<p class="sd-updated">最終更新: 〇年〇月〇日</p>`）が見える。日付は中身を変えたときだけ更新する
- 文字のコントラスト4.5:1以上、本文14px以上、タップ領域が十分
- 画像に width/height があり、ファーストビュー以外は loading="lazy"

## 点検
- `<body class="t-` がないページの数（p/index.html と Flutter SPA は除く）
- `linear-gradient` `box-shadow` `backdrop-filter` `border-radius:(9|1[0-9]|[2-9][0-9])px` を含むページの数と場所
- `<img` に width/height がないもの

## すぐ直してよいこと
- 新しいページへの `python3 scripts/apply_page_type.py {read|show|use}` の適用
- 画像の width/height・lazy の付け忘れ
- design/*.css の小さな調整と `--refresh`（見た目が大きく変わらないもの）

## 判断が必要なこと（PRにする）
- 3タイプの形・色・文字の大きさを大きく変えること、ヘッダー・フッターの作り直し
