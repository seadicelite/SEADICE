10月27日の開発日誌
— 掲示板アプリAIBOUの約束を先に決め、アプリの最初の一歩を作り直した日

2026-10-27 · SEADICE

この日は、誰でも読める匿名の防犯掲示板アプリ「AIBOU」のために、アプリを出す前に約束を先に決めた。紹介ページとプライバシーポリシーを公開前の状態で置き、七ヶ条の第六条に書き込みの扱いを足した。もう1つの大きな変更は、アプリの初回起動の考え方で、最初に出す説明をやめて「最初の一歩」から始める形に改めた。

やったこと

本体で11件、メディア側で3件のコミットがあった。本体の大半はルールと文書、メディア側は防犯の一人暮らしの記事。

分野内容
アプリAIBOU（AI時代の防犯掲示板）の紹介ページ（近日公開・検索に出さない設定）とプライバシーポリシーを追加し、プライバシーの一覧に載せた。確認待ちをやめて、書き込みはすべて公開し、通報が3件で隠す形にした。返信のない古いスレッドは90日で自動で消す。この2点を紹介ページ・ポリシー・七ヶ条に反映した
ルール七ヶ条の第六条に、誰でも読める掲示板の書き込みの扱い（消しても残る時刻と通報の記録、はじめのうちは運営が用意した書き込みが含まれること）を足した。CLAUDE.md には、利用者が自分で公開する投稿を「集めない」の例外として明記した
ルールアプリ開発の流れと役を整理した。新規は月1本、企画の関門を置く、費用は抑える、迷ったら利用者を優先する。体験役（起動から「これいい」までの設計）と実機確認役（シミュレーターで全画面を押す）を追加した
ルールアプリの初回起動を「最初の一歩」にした。ウェルカムダイアログをやめ、通知・課金・ウィジェットの案内は後で一度だけにする。許可は使う直前に求め、投稿アプリの規約同意は最初の投稿時にし、気になる情報の入力欄のそばに扱いを1行書く。「離脱しにくい画面」の8項目も足した。続けて使うアプリのために、習慣化の研究にもとづく「続く仕組み」を体験役に、「何日目か」のなりきりを利用者役に加えた
サイト支援ページから投げ銭の欄を削除し、説明文と更新日を直した。使われなくなった Cloud Function（言い訳メーカーの名残）のコードと設定も削除した。本番側の削除は人の手が必要なので manual.md に書いた
運用開発日誌を直した。10月25日の日誌は、見出しが10月24日のままだったのと、メディア側の件数（19件を106件に）を訂正した。manual.md では、AIBOU の匿名ログインを有効化済みにし、残りを App Check の登録だけにした
メディア防犯に一人暮らしの記事3本（宅配便の受け取り方、別れた相手の合鍵と鍵をなくしたとき、引っ越し先の住所を知られないために）を追加し、一人暮らしの防犯チェックの項目を25にした。このチェックはデザイン点検で、タップ領域を48pxにし、赤い警告をやめて「見直す所」の表現にし、注意書きを常に表示する形に直した

なぜ、アプリを出す前に約束を決めたのか

AIBOUは、利用者が自分で書き込みを公開するアプリ。SEADICEはこれまで「利用者のデータを集めない」と書いてきたので、投稿を預かるアプリを出すなら、先にルールの側を実態に合わせる必要があった。

  • 先に書く: 何を保存し、何を保存しないか（投稿内容と匿名IDだけ。IPや端末情報はためない）を、公開前にポリシーと七ヶ条に書いた
  • 運営の書き込みも隠さない: はじめのうちは運営が用意した書き込み（公表された手口・相談の例をもとにしたもの）が混ざることを明記した。本物の投稿に見せかけない
  • 仕組みを軽くする: 確認待ちの人手を前提にせず、通報3件で隠し、古いスレッドは90日で消す形にした

学んだこと

  1. 約束を先に決めると、作る側の迷いが減る。保存するものと消すものが決まっていれば、実装でも説明文でもぶれない
  2. 初回起動で説明を重ねると、最初の一歩が遅れる。許可や規約は、使う直前や最初の投稿の時点に回したほうが、何のための確認かが利用者に伝わる
  3. 点検役は役割を分けたほうが指摘が具体的になる。企画、体験、実機、申請前と段階ごとに役を置いて、同じ問いを何度も繰り返さないようにした
  4. 前日の日誌にも数え間違いは出る。件数は後から数え直せるので、気づいたらその日のうちに訂正する

次にやること

  • AIBOU の App Check の登録（manual.md、人の手が必要）
  • 本番の Cloud Function の削除（manual.md、人の手が必要）
  • AIBOU を出す前に、体験役と実機確認役の点検を通す
