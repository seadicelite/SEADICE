# EVIDENCEアプリのトピックを調べて追加する

研究にもとづくアプリ「EVIDENCE」と、そのサイト seadice.win/evidence/ に載せる短いトピック（カード3〜4枚）を、論文を確かめながら追加する。データは `p/apps/evidence/data/topics.json`（アプリはここを読み込むので、アプリの再申請なしで反映される）。

## 1本の形
```json
{
  "id": "英小文字とハイフン（既存と重複しない）",
  "category": "分野名（既存の分野名に合わせる）",
  "kind": "よくある説 | 素朴な疑問 | 研究紹介",
  "themeColor": "#RRGGBB（同じ分野の既存トピックと同じ色）",
  "sourceLabel": "Author et al., \"Title\" (Journal, Year)",
  "sourceUrl": "https://doi.org/<DOI>",
  "studyType": "メタ分析 | ランダム化比較試験 | レビュー | 観察研究 | 実験",
  "cards": [{"stage": "見出しラベル", "title": "...", "body": "..."}]
}
```
メディアに同じテーマの記事があるときだけ `articleUrl`（記事URL）と `articleSite`（メディア名）を付ける（URLは curl で200を確かめる）。

## 研究の種類（studyType）
- 必ず付ける。論文の方法を読んで決める（Europe PMC の pubTypeList も参考にする）
  - メタ分析: 複数の研究を数字でまとめた（系統的レビュー＋メタ分析を含む）
  - ランダム化比較試験: くじ引き等でグループを分けた介入研究
  - レビュー: 数字でまとめない文献の整理
  - 観察研究: 調査・追跡・データ分析（介入しない）
  - 実験: 条件を変えて試したが、上のどれでもないもの
- 人を対象にしない研究: AIの出力などを集めて評価したものは「観察研究」、力学モデルなど条件を変えた計算は「実験」。結論のカードで「人での検証ではない」ことを必ず書く
- 古いトピックを直すときも、studyType がなければ付ける
- 弱い種類（観察研究・実験）のときは「まだわからないこと」で、その弱さを具体的に書く

## 書き方
- 友だちに話すように。「〜だよね」「実は」「〜らしい」はOK。1枚の本文は120字前後まで。カード3〜4枚、見出し（stage）は自由
- **最後か最後から2枚目に必ず「まだわからないこと」**：相関か因果か、対象者（国・年齢・人数）、実験室の話か、再現されたか
- 結論は研究のとおりに書く。問いに都合のいい答えにしない。混ざった結果なら「混ざっている」と書く
- 「証明された」「絶対」「〜で治る」は使わない。病気の診断・治療の助言、商品のおすすめ、人を操る方法は扱わない
- 有名な元の研究を紹介するときも、出典は追試・メタ分析などいちばん新しく強い研究にする

- **「よく聞く説」「素朴な疑問」から始めるときは、結論のカードの stage を「ほんとのところ」か「わかったこと」にする**。サイトの説明文と FAQ の答えはこのカードから作られるので、名前が違うと説そのものが答えとして出てしまう（2026-10-12 に実際に起きた）
- **わかったことを書くカードの stage は「結果」「ほんとのところ」「わかったこと」のどれかにする**。アプリはこの3つを明るく強調し、「まだわからないこと」は灰色で控えめに出す。別の名前にすると、わかったことが強調されない
- **数字には大きさの目安を添える**（2026-11-27、利用者役が「g=0.4 がどれくらいかわからない」と指摘）。効果量 g・d は「0.2で小さい・0.5で中くらい・0.8で大きい」、相関 r は「0.1で小さい・0.3で中くらい」、ハザード比・リスク比は「0.82＝約2割低い」のように言い換える。p 値・NeuN などの専門語は、なくても話が通じるなら書かない
- **結論の見出しは、見えた事実をはっきり書く**（2026-11-28 に直した。11-27 の「見出しで言い切らない」が効きすぎ、結論の見出しの36%が「〜低め」「〜傾向」「〜関係」にぼけた。ユーザー「どっちつかずの回答が多い」）
  - 言い切ってよいのは、データで見えた事実（誰が・何が・どれだけ）。例「笑う場面が多い人は、認知症が16%少なかった」「1週間休んだ組は、満足度が上がった」「差はなかった」
  - 言い切らないのは、因果と効能だけ。観察研究で「〜すると下がる」「〜で防げる」と書かない
  - 「〜め」「〜傾向」「〜関係が見られた」で数字をぼかさない。注意書きは最後の「まだわからないこと」1枚にまとめ、ほかのカードにくり返さない
- **答えが出ている研究を選ぶ**（同日）。メタ分析・大きな試験・よく聞く説の検証など、結論がはっきりしたものを優先する。信頼区間が0や1をまたいで答えが出ていない研究や、「証拠の確かさがとても低い」とされた研究は、「効かなかった」がよく聞く説への答えになるときだけ使う
- **クイズの誤答は、読まずには選べないものにする**（同日）。「約2倍」「r=0.8」「明らかに効いた」のような極端な誤答や、見出しそのままの正解は、読まなくても当たる。よくある思い込みか、近い数字を誤答にする。正解は研究の言い方より強くしない（「〜が一因」を「〜だから」にしない）
- **論文にない推論を書かない**（同日、出典確認で2本見つかった）。「集められた研究はそれより前のもの」「もともとの違いかは切り分けられない」なども要旨になければ書かない。対象者の範囲も広げない（高齢者の介護者全般を「親の介護」にしない）

## 事実の確かめ方（省略しない）
- DOIは https://api.crossref.org/works/{DOI} で実在・タイトル一致・撤回されていないこと（update-to / relation に retraction がない）を確かめる
- 要旨も本文も読めず数字を確かめられない説（例: 1967年の論文で要旨がない「メラビアンの法則」）は書かずに見送り、docs/improve/evidence.md の「次にやること」に残す
- 数字・人数・国・条件・所属は、論文の要旨か本文（Europe PMC: https://www.ebi.ac.uk/europepmc/webservices/rest/search?query=DOI:{DOI}&resultType=core&format=json 、なければ PubMed や出版社ページ）で確かめたものだけ書く。確かめられない数字は書かない
- データの不正が指摘された研究者・撤回された論文は使わない
- Europe PMC・Crossref に接続できない環境では、新しいトピックは作らない。既存トピックに「まだわからないこと」だけを足すときは、カードにすでにある対象・人数・方法から書き、数字や新しい事実は足さない（要旨との照合は手元で行い、次にやることに残す）
- 外部サービスに個人情報を送らない（DOIやキーワードで公開APIを引くだけ）

## 研究どうしをつなぐ（links）
- 新しいトピックを足すときは、既存のトピックに同じ問い・とても近い問いのものがないか探す
  - 結論が分かれる（元の研究と追試、効果ありと効果なし、対象者で結果が違う）→ `"type": "反対の結果"`
  - 片方がもう片方を深める（仕組みとやり方、メタ分析と1つの実験）→ `"type": "あわせて読む"`
  - 同じ分野というだけではつながない。読み終えた人の役に立つときだけ
- 両方のトピックの `links` に `{"id": 相手のid, "type": ..., "why": "60字以内の理由（例: 同じ問いで、追試では効果が見られなかった）"}` を入れる（片方だけにしない）。1本につき最大3つ。相手がすでに3つ埋まっているときは、新しい側からも張らない（上限を超えるか片側だけになるため。どうしても要るなら相手の一番弱いリンクと入れ替える）

## 検索されている説は1問1ページにする
- Googleの検索候補（`https://suggestqueries.google.com/complete/search?client=firefox&hl=ja&q=説の名前 嘘` など、「嘘」「論文」「根拠」「本当」を付けて引く）に候補が出る説は、検索されている
- その説のトピックは `p/apps/evidence/data/focus.json` に `{"kw": 検索語, "title": "〇〇は本当？ 論文でわかったこと"}` で入れる。title は中身と合う言い方にする（「嘘と証明」のように言い切らない）
- 追加・変更したら `python3 scripts/build_evidence_hub.py` で再生成する

## 重複させない
- 既存の topics.json の id・タイトル・sourceUrl と比べ、同じ研究・同じ問いは書かない
- sourceUrl は `https://doi.org/` の形にそろえる（PubMed や出版社のURLのままだと、同じ論文の重複に気づけない。2026-10-13 に同じ論文のトピックが4組見つかった）。比べるときは DOI・PMID を取り出して比べる
- 足したあと、同じ DOI のトピックが2本以上ないかを必ず数える（`python3 -c` で topics.json の sourceUrl から DOI を取り出して数える）。1本でも出たら、そのコミットで片方を外すか、判断待ちとして docs/improve/evidence.md に書く。コーヒーの脱水（myth-coffee-dehydration と caffeine-coffee-dehydration-crossover、2026-11-06 の取り込みで重複）が出たため
